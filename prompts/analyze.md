CLAUDE.md に定義されたコンテナ化ポリシーに従ってください。
Before/After の構成図は Mermaid 形式のコードブロックとして stdout に出力すること（ファイル書き込みツールは使用しない）。

Mermaid 図を生成する際は以下のシンタックスルールを**必ず**守ること:
- `graph TD` のみ使用する（`flowchart` キーワードは使わない）
- ノード ID に空白・ハイフン・括弧・特殊文字を含めない（英数字とアンダースコアのみ）
- ラベルに括弧や特殊文字を含む場合は `["ラベル"]` 形式で囲む
- エッジは `-->` のみ使用する（`==>`, `-.->`, `---` は使わない）
- `subgraph` のラベルに特殊文字やスペースを含めない
- 各ノード ID は図内で一意にする

対象のソースコードリポジトリを解析し、コンテナ化設計ドキュメントを Markdown で出力してください。
前置きは不要です。以下のフォーマットでドキュメントを直接出力してください。

---

| ランタイム | ... |

## 外部依存サービス

アプリが依存するデータベース、キャッシュ、キュー、外部 API などを列挙してください。

## 環境変数

ソースコードから検出した必須・任意の環境変数を列挙してください。JWT シークレット等の認証系変数がある場合は、使用ライブラリが要求する最小ビット長（例: HMAC-SHA256 系アルゴリズムは 256 bit = 32 バイト以上）を合わせて記載すること。

## コンテナイメージ一覧

| サービス名 | 種別 | イメージ / ベースイメージ | 説明 |
|-----------|------|--------------------------|------|
| （例）app | 新規ビルド | `<runtime>:<version>-alpine` ベース | ソースからビルドする独自イメージ |
| （例）db  | 外部イメージ | `<software>:<version>-alpine` | Docker Hub 公式イメージをそのまま使用 |

※ 種別は「新規ビルド」（Dockerfile でビルドするもの）または「外部イメージ」（公式イメージをそのまま使用するもの）のいずれかを記載すること。

## コンテナ化ノート

- ビルド戦略の根拠
- ベースイメージの推奨と選定理由
- 特記事項（ボリューム、シークレット、ヘルスチェック）
- 注意すべき潜在的な問題点
