CLAUDE.md に定義されたコンテナ化ポリシーに従ってください。

コンテナ化されたアプリケーションが正常に動作していることを検証する bash テストスクリプトを生成してください。

## ロードバランサーのテスト方針

LB の動作確認は「LB エンドポイントが正しい HTTP ステータスを返すこと」と「全バックエンドが healthcheck を通過していること」で十分。アプリコンテナのログを使った分散確認（どちらのインスタンスにリクエストが届いたか）は行わないこと。多くのフレームワークはデフォルトでリクエストをログ出力しないため、この方法は信頼性がない。

## PostgreSQL / DB サービスのテスト方針

DB サービスの動作確認は `pg_isready` や SQL（`pg_is_in_recovery()`、`pg_stat_replication` など）で行うこと。コンテナログの起動メッセージ検索（`docker logs ... | grep "ready to accept"`）は禁止。理由:
- `--tail` を使うと起動直後のメッセージを見逃す
- `--tail` なしはログ全量を取得するため重い
- `pg_isready` や SQL は確実かつ軽量

## 出力フォーマット

bash スクリプトの内容のみを stdout に直接出力してください。ファイル書き込みツールは使用しないでください。**必ず `#!/usr/bin/env bash` で始めてください（これが出力の最初の行でなければなりません）**。Markdown のコードフェンスで囲まないでください。スクリプトの前後に説明文を含めないでください。
