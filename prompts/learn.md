CLAUDE.md に定義されたコンテナ化ポリシーに従ってください。

これは wraptainer パイプラインの **学習ステップ（Step 7: learn）** です。

## 目的

wraptainer は「様々なアプリをコンテナ化 → デプロイ → テスト」を繰り返すツールです。各実行で発生した失敗と自動修正から**再発防止のための一般知識**を抽出し、`CLAUDE.md` と `prompts/` 配下のプロンプトへ反映します。これを毎回積み重ねることで、ポリシー文書が回を追うごとに精度を増し、次のアプリでは同じ失敗を最初から避けられる状態を目指します。

今回の実行では最終的にすべてのテストが PASS しました。そこに至るまでの自動修正の記録（修正ジャーナル）と最終成果物を渡します。

## 入力

- **修正ジャーナル**: 今回の実行で発生した失敗と、それが解消されるまでの試行の記録
- **最終成果物**: 最終的にテストを通した Dockerfile / docker-compose.yml / テストスクリプト
- **編集対象のポリシーファイルのパス**

修正ジャーナルの試行番号と実際に修正されたファイルの対応:

| フェーズ | 試行 | 自動修正の対象 |
|---------|------|--------------|
| deploy | 1 | Dockerfile |
| deploy | 2 | docker-compose.yml |
| deploy | 3 | Dockerfile + docker-compose.yml |
| deploy | ネットワーク再作成レース検出時 | 何も変更せずクリーン再デプロイで再試行（Makefile が処理済み） |
| test | 1 | テストスクリプト |
| test | 2 | docker-compose.yml + 再デプロイ + テストスクリプト再生成 |
| test | 3 | テストスクリプト再生成 |

## 更新のルール（厳守）

1. **汎用性のみ**: 追加するガイダンスは特定アプリ・特定バージョン・特定の値に依存しないこと。アプリ名・テーブル名・ポート番号・固有のパッケージ名などを書かない。言語/ミドルウェア共通で成り立つ再発防止策だけを一般化する（「Java WAR 全般」「PostgreSQL レプリカ全般」など粒度を上げる）。
2. **再発可能性で取捨選択**: そのアプリ固有のタイプミスや一度きりの事象は対象外。別のアプリでも同じ落とし穴にはまりそうなものだけを追加する。判断がつかないものは追加しない。
3. **重複を作らない**: 追加前に対象ファイルを Grep し、同等のガイダンスが既にあれば **何も変更しない**。既存の記述で不十分な場合のみ、その箇所に最小限追記する。
4. **既存記述を壊さない**: 既存の行の削除・意味を変える書き換えをしない。該当セクションへの簡潔な箇条書き追加のみ。
5. **肥大化を防ぐ**: 1 項目 1〜4 行。既存の複数項目と重複気味なら、新規追加ではなく既存項目への語句追加で対応する。ポリシーは「増やす」より「精度を上げる」ことを優先。
6. **正しい配置先**:
   - 生成物すべてに関わる原則 → `CLAUDE.md` の該当セクション（解析 / Dockerfile / docker-compose / テスト / セキュリティ）
   - 生成時の指示 → `prompts/dockerize.md`（Dockerfile 生成）、`prompts/deploy-yaml.md`（compose 生成）、`prompts/test.md`（テスト生成）、`prompts/analyze.md`（解析）
   - 自動修正時の指示 → `prompts/fix-dockerfile.md` / `prompts/fix-compose.md` / `prompts/fix-test.md`
   原則を `CLAUDE.md` に、その原則を適用する具体的パターンをプロンプト側に、と役割分担する。
7. **日本語で書く**。**Makefile は編集しない**（実行フロー自体の問題は変更サマリーで指摘するだけ）。

## 手順

1. 修正ジャーナルを読み、失敗を「クラス」に分類する（例: ベースイメージのタグ不在、依存サービスの起動順、シェルエスケープ、テストの誤検知 など）。
2. 各クラスについてルール 1〜5 で採否を判断する。
3. 採用するものだけ、Edit ツールで該当ファイルに追記する。
4. 変更した各ファイルについて、1 行で「何を・なぜ追加したか」を stdout に出力する。何も追加しなかった場合は「学習対象となる汎用的な再発防止策はなし（既存ポリシーで対応済み）」と出力する。

出力は上記の変更サマリーのみ。ポリシーファイルの全文を stdout に出力しないこと。
